4. 零追蹤：紀念摯愛的姓名與照片僅存於手機，不收集任何資料。
5. 莊重克制：不隸屬任何寺院教派、不宣稱宗教功效、不替代專業臨終關懷——此免責聲明是信任資產，永久保留。

## 二、關鍵詞策略（依 2026-07 真實 SERP 研究）

分層（P0 → P3）：
- **P0（index title/H1 主戰場）**：臨終助念 App、助念 App、念佛機 App、臨終助念念佛、阿彌陀佛聖號。依據：核心裸詞（臨終助念／助念／往生助念）SERP 被寺院權威站壟斷（諾那華藏 e-lotus、法鼓山、華藏淨宗、中台世界）＋禮儀公司知識頁，無任何 App 落地頁占位——裸詞不強攻，「臨終助念 App」等組合詞幾乎空白，是最高性價比切入點。
- **P1（功能區／description）**：助念機、佛號整夜連續播放、心經 App、免費結緣、完全離線、防誤觸。依據：「聖號 8小時（助念版）」有專門音頻 SERP、「助念要念多久」標準答案即 8~12 小時；「念佛機 結緣 免費索取」有專門 SERP；「病房無網路播佛號」「零廣告」「防誤觸」為無人書寫的內容空白。注意：「8 小時」僅作為搜尋詞由 FAQ「助念要念多久」（傳統為 8~12 小時的事實陳述）承接；站內對 App 本身的表述一律用實際檔位「1、2、4、8、12 小時與不限時」與「整夜連續播放」，不得寫成「最長 8 小時」（App 實際上限為 12 小時＋不限時）。
- **P2（support FAQ 長尾）**：助念要念多久、電子念佛機代替助念嗎、半夜往生怎麼辦、四字六字佛號、醫院病房念佛、念佛機整夜播放。依據：法鼓山〈可以用電子念佛機代替助念嗎〉長期第一，法師共識「人助念為上、無人時機器為助緣」——恰好符合本站「不宣稱宗教功效」約束；深夜緊急場景詞（助念團需申請等待，App 即開即用）轉化最高。
- **P3（僅對照，不落地）**：簡體詞（念佛机、临终助念、电子木鱼）。見第六節。
- **明確避開**：電子木魚迷因詞（「功德+1」解壓文化，與臨終莊重氣質錯位，僅以「木魚、引磬法器音」自然帶過）；不硬拼裸詞「臨終助念／助念」首頁排名（權威碾壓）。
- **FAQ 富結果現實預期**：Google 自 2023 年 8 月起僅向知名權威的政府與健康類網站展示 FAQ 富結果，本站不應預期取得該版位。support 頁 FAQPage 結構化資料的實際價值在於語意標註（讓搜尋引擎準確理解問答內容）與生成式搜尋摘要、答案引擎的引用；長尾流量仍由 FAQ 頁面文字本身承接。

## 三、SERP 與競品現狀摘要

- 「臨終助念」首頁：寺院／基金會知識頁壟斷＋殯葬業問答式 SEO 文，零 App 結果；搜尋意圖=家屬急需操作指引。
- 「念佛 App」類詞：商店頁＋低質聚合站（softonic/appbrain），繁中圈無一篇像樣的編輯型 App 推薦文。
- 唯一直接競品：諾那華藏精舍「助念機」App（App Store id537086904，免費、不收集資料、40 年助念團背書，但產品老舊）。其餘念佛 App 全部瞄準日常修行（計數／目標／3D 念珠／iCloud 統計），無一為「病房／床邊／離線／防誤觸」設計。
- 「阿彌陀佛聖號八小時」需求大量落到 YouTube 8 小時影片——需網路、插廣告、鎖屏即停；寺院免費結緣播經機長期流行，證明「離線連續免費播佛號」是真實剛需。
- 語氣基準（蓮花基金會、法鼓山、諾那華藏）：陪伴動詞＋結果留白（絕不承諾往生）＋去商業化「結緣」語彙＋對家屬的體貼須知。

## 四、CJK 標題與描述長度規範（為何不是拉丁字符的 50-60／120-155）

- Google 桌面搜尋結果 title 顯示寬度約 600px。拉丁字符約可容 50~60 字元，但 CJK 全形字的顯示寬度約為拉丁字符的兩倍，600px 僅能容納約 30 個全形字——故本站 title 標準為 **≤30 全形字**（英文字母／半角符號按 0.5 個全形字計），核心關鍵詞前置以防截斷。
- meta description 拉丁標準 120~155 字元，換算 CJK 約 **60~80 全形字**；行動版截斷更早，最重要的轉化鉤子應盡量前置：三頁 description 的首要鉤子（index「完全免費」、support「使用說明與常見問題」、privacy「不收集、不上傳、不分享」）均已置於前 40 字內；「無廣告、不收集任何資料」「整夜連續播放說明」等尾部鉤子落於 60~80 字區間，行動版可能被截斷，屬已知且可接受的取捨。
- 本站現行值：index title 27.0／description 75.0；support 24.5／68.5；privacy 22.0／71.5。

## 五、robots.txt 與 GitHub Pages 子路徑限制

- 搜尋引擎僅讀取**域名根**的 robots.txt（https://jaydencj.github.io/robots.txt），該檔案屬使用者根站點，本倉庫無法控制；倉庫內 /changminglamp-site/robots.txt 及其中 Sitemap 指令**永遠不會被讀取**。
- 因此收錄控制實際依靠：各頁 meta robots、canonical、以及在 Google Search Console 手動提交 sitemap.xml。
- 倉庫內 robots.txt 保留無害，不再維護；若未來綁定自訂網域（robots.txt 屆時生效），再行補全。

## 六、百度與簡體市場現狀（僅對照，不投入）

- 可達性：github.io 在中國大陸連線長期不穩定（間歇性受干擾），百度對 GitHub Pages 的收錄與排名極差。
- 需求錯位：簡體「念佛机」語境指實體硬體（品牌榜、1688 批發）與安卓渠道 App；「临终助念」內容被寒山寺、新浪佛學等大陸宗教站壟斷；「电子木鱼」=娛樂迷因。
- 產品錯位：App 僅 iOS、站點 zh-Hant；簡體使用者天然可讀繁體頁，無需專門優化。
- 路線圖：App 介面已支援簡體。若未來確有簡體使用者需求，優先做 zh-Hans 鏡像頁＋hreflang 互指（zh-Hant／zh-Hans／x-default），而非投入百度 SEO。本輪不做。

## 七、Google Search Console 提交步驟

1. 開啟 https://search.google.com/search-console，新增資源，類型選「網址前置字元」，填入 https://jaydencj.github.io/changminglamp-site/。
2. 驗證擁有權：建議「HTML 檔案」法（將 Google 提供的 googleXXXX.html 放入倉庫根目錄並部署）；或「HTML 標記」法（在 index.html head 加入 google-site-verification meta——此為靜態驗證標記，非追蹤資源，合規）。
3. 驗證通過後，左側「Sitemap」提交：https://jaydencj.github.io/changminglamp-site/sitemap.xml。
4. 「網址審查」逐一輸入首頁、support、privacy 三個網址，各按「要求建立索引」。
5. 內容更動後：bump sitemap lastmod → 重新提交 sitemap → 對變動頁再次要求建立索引。
6. 每月檢視「成效」報表（查詢／曝光／點擊／排名），將實際帶來曝光的查詢詞反哺至 FAQ 與文案迭代。

## 八、App 上架 App Store 後的迭代清單

1. 全站加入**真實** App Store 連結：hero 新增主 CTA「前往 App Store 下載」（btn primary），store-note「即將上架 App Store」移除；footer 可加商店連結。
2. index head 加 `<meta name="apple-itunes-app" content="app-id=真實ID">`（Safari 原生 Smart App Banner，非追蹤資源）。
3. MobileApplication JSON-LD 補：downloadUrl／installUrl（商店連結）、datePublished（真實上架日）、screenshot（真實截圖 URL）；**累積真實評分後**才加 aggregateRating（Google 軟體富摘要的必要條件）。
4. og-image 可換為含 App 實機畫面的版本（仍自託管）。
5. ASO 聯動：App Store 名稱／副標題／關鍵字欄與網站 title 同軸（臨終助念、念佛機、免費、離線）；商店描述首段複用本站 description 語彙，保持搜尋—商店一致性。
6. sitemap lastmod bump ＋ GSC 重新提交；meta description 可加「App Store 免費下載」轉化鉤子（重算 60~80 全形字）。
7. 屆時重跑 CI 全套（html-validate／check-links／Playwright）。

## 十一、頁面級取捨備忘

- privacy 頁 title 保留英文「Privacy Policy」：本頁同時作為 App Store 送審填寫的隱私政策網址，審核人員與英文使用者會直接尋找該字樣。
- 404 頁維持 noindex，另備一句 meta description 僅為分享／預覽場景兜底，不參與收錄；該頁自足性設計（內嵌樣式、`/changminglamp-site/` 絕對前綴）不可破壞。
- 不加 Organization 結構化資料：本專案為個人公益性質，除聯絡郵箱外無可核實的正式組織名稱，虛構組織實體不可取；待有正式主體時再補（同理不加 author／publisher）。
- twitter:title／twitter:description 暫不重複聲明：Twitter 卡片依規範回退至 og:*，若日後需要平台專屬文案再單獨補。
- og:image 分頁化（未來可選）：現有 og-image.png（1200×630）三頁共用；若要提升分享點擊率，可為支援頁／隱私頁各出一張帶頁面主題文字的變體圖，仍須自託管、不得引入外部資源。
- 綁定自訂網域時：整批更新 canonical、og:url、sitemap 與 404 頁的子路徑前綴，並補全屆時才會生效的 robots.txt（見第五節）。
